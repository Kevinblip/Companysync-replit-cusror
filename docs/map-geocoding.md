# Map Server-Side Geocoding

The Map page persists lead/customer coordinates on the server so pins load instantly (previously the browser geocoded ~850 addresses live on every visit, which stalled mobile and showed 0 pins).

- **Coordinate storage**: leads/customers are dedicated tables with NO lat/lng columns; coordinates live in each row's `data` JSONB (`lat`, `lng`, `latitude`, `longitude`, plus `geocoded_address`/`geocoded_at`). Both the dev (`vite-db-plugin.js`) and prod (`db/prod-db.cjs`) entity layers flatten `data` JSONB onto the entity **only when the top-level column is empty**, so `data.lat` surfaces as `lead.lat`/`customer.lat` and feeds the Map's `preCoords` → pins render.
- **`bulkGeocodeEntities` handler**: single source of truth in the vite `functionHandlers` registry (`vite-functions-plugin.js`, right after `geocodeAddress`). Dev serves it via `/api/functions/invoke`; **prod reaches the SAME handler** through `db/prod-integrations.cjs` `handleFunctionInvoke` → `getFunctionHandlers()` generic fallthrough (same pattern as `runLaunchTest` — no duplication). It selects un-geocoded rows (`NULLIF(data->>'lat','') IS NULL OR NULLIF(data->>'lng','') IS NULL`), builds+dedupes addresses (mirroring Map.jsx address construction), geocodes (Google primary, concurrency 8; gentle capped Nominatim fallback — 25 max, 1100ms apart), then persists coords via tenant-guarded idempotent UPDATE (`data = COALESCE(data,'{}')::jsonb || $1::jsonb WHERE company_id=$2 AND id=ANY($3::text[])`). Returns `{success, candidates, unique_addresses, processed, geocoded, updated_leads, updated_customers, remaining}`.
- **Authorization**: the handler is mutating and burns geocoding quota, so it does NOT trust the client-supplied `company_id`. It resolves the caller via `getUserFromRequest(req)` and requires either a platform super-admin OR a member of that company (owner via `companies.created_by`, or a `staff_profiles` row scoped to it), matched case-insensitively. Unauthenticated calls return `Authentication required`.
- **Map trigger** (`src/pages/Map.jsx`): a background `useEffect` (deps `[myCompany?.id, queryClient]`, guarded by `serverGeocodeRef` so it's StrictMode-safe and runs once per company) loops up to 6× calling `bulkGeocodeEntities` (`limit:300`); when `data.geocoded>0` it invalidates `['leads-map', companyId]` + `['customers-map', companyId]` so new pins appear, and breaks when `!remaining || !geocoded`. The client-side in-browser geocode is now capped at 40 unique addresses (`CLIENT_GEOCODE_CAP`) purely as a first-visit safety net — the server fills the rest.
- **No cron**: the Map-load trigger is sufficient (backfills existing rows within a few visits and picks up new records on the next Map open). A scheduled cron was intentionally skipped.
