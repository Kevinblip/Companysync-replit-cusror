# AI Systems Audit (pre-launch)

A full audit of every AI-powered handler (CrewCam photo analysis, AI roof measurement, gemini roof measurement, report extraction, satellite vision analysis) was completed pre-launch. Summary:

- **Fixed — usage/cost gating gap**: `checkAIUsage`/`incrementAIUsage` now gate the AI handlers that previously ran fully unmetered/unauthenticated: `refinePitchFromElevation`, `analyzeEstimateCompleteness`, `generateMasterNarration` (both the dev registry copy AND a separate prod-only interceptor in `db/prod-integrations.cjs` that had drifted from it), `generateMaterialList`, `transcribeVoiceNote`, `analyzeContractTemplate`, `geminiTTS`, `generateMarketingCopy` (its unauthenticated prod-only duplicate was removed entirely so it now falls through to the same gated dev registry handler), and `lexiChat` (again both the dev copy and a separate prod-only `handleLexiChat` duplicate). `company_id` resolution was added to `getUserFromRequest` (with `staff_profiles` fallback) so every handler can identify the tenant to gate/bill. This list reflects the handlers actually touched — not a claim that literally every AI-calling code path in the app is gated; see "Deferred" below for what's intentionally left for later.
- **Fixed — direct `_xxxImpl` bypass**: both dispatchers (`vite-functions-plugin.js` and `db/prod-integrations.cjs`) now reject direct calls to the internal `_xxxImpl` functions (403 `Not a callable function`) so a client can't skip the wrapping handler's auth/usage-gate logic by naming the impl function directly.
- **Fixed — dev/prod handler drift**: `db/prod-integrations.cjs` had a stale, duplicate `handleAIRoofMeasurement` intercept that had drifted from the dev implementation; removed so prod falls through to the same shared registry handler dev uses (same pattern as `runLaunchTest`/`bulkGeocodeEntities`). The audit found this same "prod keeps its own duplicate copy" pattern recurring for `lexiChat`, `generateMasterNarration`, and `generateMarketingCopy` — every handler intercepted by name inside `db/prod-integrations.cjs` before the generic registry fallthrough was checked for a duplicate implementation that can silently drift out of sync with (or skip auth entirely relative to) dev.
- **Fixed — dead/orphaned handlers ported into the live registry**: `extractEstimateGPT4o` and `analyzeSatelliteImage` existed only as unused Deno functions in `functions/`; both were ported into the `vite-functions-plugin.js` handler registry (the single source of truth serving both dev and prod) with local equivalents of their external calls (local PriceListItem query, `callGemini`, `uploadToObjectStorage`), and wired into the same auth/usage-gate/logging pattern as the other AI handlers.
- **Fixed — hardcoded test-hack overrides removed**: address-keyed special-case overrides (Mardale/2184) in `geminiRoofMeasurement` were removed; no equivalent generalized mechanism was needed since they were only ever meant for one-off testing.
- **Fixed — missing timeouts**: `callGemini`, `callGeminiMultiImage`, and the OpenAI fetch in `extractEstimateGPT4o` now have a 60s `AbortController` timeout so a hung upstream API call can't tie up a request indefinitely.
- **Fixed — blind trust in AI JSON output**: added `assertAIShape()` (near `callGemini` in `vite-functions-plugin.js`) which throws a clear error when an AI JSON response is empty/malformed or missing every expected field, instead of silently proceeding with an all-defaults payload reported as `success: true`. Applied to `analyzeCrewCamPhotoAdvanced` (guards `callGeminiMultiImage`'s silent `{}`-on-parse-failure fallback) and `extractEstimateGPT4o` (guards against a well-formed-but-empty extraction). Other handlers (`analyzeCrewCamPhoto`, `aiRoofMeasurement`, `geminiRoofMeasurement`, `analyzeSatelliteImage`) already had adequate per-call/per-photo validation or graceful degradation and needed no change.
- **Confirmed single source**: all six originally-audited handlers exist in `vite-functions-plugin.js`, which is the live registry in development and production. Their obsolete standalone Deno counterparts were removed so source inspection cannot mistake them for runtime code.
- **Fixed — `processCheckPayment` usage gating**: was calling Gemini for check-reading with no usage gate; now wrapped with `requireGatedCompany` like the other AI handlers (no prod-only duplicate existed for this one).
- **Fixed — consistent timeout/retry on EVERY live AI HTTP call site (not just the originally-scoped handlers)**: a repo-wide audit found many more raw `fetch()` calls to Gemini/OpenAI outside the six originally-audited handlers, each with inconsistent (or no) timeout/retry handling. All were migrated to a shared `fetchWithRetry` helper (timeout via `AbortSignal.timeout`, bounded retries with linear backoff on abort/timeout/429/5xx, no retry on other 4xx):
  - ESM Vite plugins (`vite-functions-plugin.js`, `vite-integrations-plugin.js`, `vite-lexi-native-plugin.js`, `vite-twilio-ws-plugin.js`) each define/import their own `fetchWithRetry` (no cross-import between separate Vite plugin modules); ESM files without a sibling copy require the CJS helper via `createRequire`.
  - CJS backend modules (`prod-server.cjs`, `db/prod-db.cjs`, `lib/smsAssistant.cjs`) import the shared `lib/fetchWithRetry.cjs` module. `db/prod-integrations.cjs` keeps its own mirrored inline copy (CommonJS, no cross-import history with the Vite plugins) rather than switching to the shared module, to avoid touching its already-verified call sites.
  - Covered call sites: `callGemini`/`callGeminiMultiImage`/`callGeminiWithSchema` and their duplicates, `extractEstimateGPT4o`'s OpenAI call, `geminiTTS` (including the Sarah voice-preview TTS call in `vite-twilio-ws-plugin.js`), the Lexi tool-loop turn call and `scan_check` inline call (all 4 dev/prod × text/voice copies), the SMS assistant's Gemini tool-loop (`lib/smsAssistant.cjs`), the call-synopsis Gemini call (both `prod-server.cjs` and `vite-twilio-ws-plugin.js` copies), and the `/api/local/test-api-key` / `test-api-key`-equivalent Gemini validation calls in both dev and `db/prod-db.cjs`.
  - Out of scope (intentionally not migrated): remaining standalone Deno functions not represented in the live handler registry; `railway/server.js` (unreferenced alternate deploy target, not in `package.json`); `wss://` Gemini Live `BidiGenerateContent` connections (WebSocket, not `fetch` — resilience there means reconnect-on-drop, already handled by the existing Gemini Live reconnect logic, not a request-level retry).
- **Deferred (post-launch)**: consolidating the several near-duplicate Gemini prompt/parsing helpers; extending `assertAIShape` coverage to the Lexi/Sarah voice bridge's structured tool-call outputs.
