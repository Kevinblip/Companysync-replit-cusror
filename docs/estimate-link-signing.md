# Public Estimate Link Signing (HMAC)

Public `/ViewEstimate?id=…` URLs are signed with an HMAC-SHA256 token (`&t=…`) so an estimate ID alone is not enough to view, approve, or download the PDF.

- **Helpers**: `lib/estimateToken.cjs` (Node/CJS, used by dev plugins and `prod-server.cjs`) and `functions/_estimateToken.ts` (Deno, used by Base44 production functions). Both derive tokens from `ESTIMATE_LINK_SECRET` (falls back to `SESSION_SECRET`) and use `base64url(HMAC_SHA256(secret, estimateId))`.
- **URL emitters** that now append `&t=…`: workflow email enrichment (`vite-functions-plugin.js` ~ln 760), `sendEstimateEmail` (~ln 7850), in-app notification helpers (`vite-notification-helper.js`, `db/prod-db.cjs`), and the text-message paths in `src/pages/Estimates.jsx` and `src/pages/EstimateEditor.jsx` (which call `getEstimateShareLink`).
- **`getEstimateShareLink` authorization**: the handler in `vite-functions-plugin.js` runs in dev *and* production (it used to refuse whenever `NODE_ENV === 'production'`, which meant a texted or emailed estimate arrived with no link in the live app). It is safe to run in production because it now authorizes the caller in-handler: caller email comes from the session, the estimate's `company_id` is looked up in `estimates` then `generic_entities`, and the caller must hold an **active** (`is_active IS NOT FALSE`) `staff_profiles` row in that company — multi-location staff are matched against every company they belong to, emails compared case-insensitively. Any error fails closed, and an unsignable request returns an error rather than an unsigned URL. Covered by `scripts/test-estimate-share-link-authz.cjs`. The stale Deno copy has been removed; treat the Vite registry as the only implementation.
- **No caller may fabricate an unsigned link**: `src/pages/Estimates.jsx` previously fell back to a bare `/ViewEstimate?id=…` when signing failed. That fallback is gone; a send now fails loudly instead of texting a customer's pricing out on an open URL.
- **Endpoints that validate**: `getPublicEstimate`, `updatePublicEstimateStatus`, and `/api/public-estimate-pdf` in dev (`vite-functions-plugin.js`); `functions/getPublicEstimate.ts`, `functions/updatePublicEstimateStatus.ts`, `functions/publicEstimatePDF.ts` in prod. Frontend `src/pages/ViewEstimate.jsx` reads `t` from the URL and forwards it.
- **Rollout mode**: defaults to MONITOR — missing tokens are logged but allowed so unread legacy emails keep working; **invalid** tokens are always rejected. Set `ESTIMATE_REQUIRE_TOKEN=1` in production to enforce after monitoring confirms 100% of legitimate traffic carries tokens.
- **Tests**: `scripts/test-estimate-token.cjs` covers determinism, base64url charset, mismatched-id rejection, constant-time tampering, monitor vs enforced modes, and secret rotation (18 assertions). Wired into `scripts/post-merge.sh`.
- **Base URL resolution**: all `estimate_url` / share-link emitters in `vite-functions-plugin.js` call a single `getAppUrl()` helper. In the Replit dev workspace (`REPLIT_DEPLOYMENT !== '1'`), it returns the workspace's own `REPLIT_DEV_DOMAIN` instead of the hardcoded production domain — otherwise a test estimate created only in the dev database would generate a link pointing at production, which 404s ("Estimate Not Found") because the record doesn't exist there. Do not reintroduce inline `process.env.VITE_REPLIT_APP_URL || 'https://getcompanysync.com'` fallbacks; always call `getAppUrl()`.
