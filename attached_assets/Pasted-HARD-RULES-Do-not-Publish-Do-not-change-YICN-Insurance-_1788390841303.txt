WHAT BROKE
Live proof on getcompanysync.com after tonight’s publish: a brand-new company (Wizard Test Two) opened Quick Setup → Integrations → Phone & SMS. Status was “Not connected” (good — no Twilio row for that company). But Account SID showed io.companysync@gmail.com and Auth Token was filled with dots. Phone was still the empty placeholder. Nobody clicked Save.

That SID value is an email, not a Twilio AC… SID. The Quick Setup form state starts as empty strings. So this is almost certainly the browser autofilling the saved getcompanysync.com login into Account SID (looks like a username) and Auth Token (type=password). A real subscriber on their own computer would get THEIR saved login stuffed in, or ours if they ever used this browser. Either way the fields must never look prefilled.

Keep last night’s save-guard: reject saving a SID/phone that belongs to another company, YICN, or the master account.

FIX (small, only Quick Setup Twilio fields + the GET that feeds them)
1) On Quick Setup Integrations Twilio inputs:
   - Account SID: autoComplete="off", name="twilio_account_sid", placeholder stays AC…
   - Auth Token: type="password", autoComplete="new-password", name="twilio_auth_token"
   - Phone: autoComplete="off", name="twilio_phone_number"
   - Put autoComplete="off" on the wrapping form/card too.
2) Never copy process.env TWILIO_ACCOUNT_SID / TWILIO_AUTH_TOKEN / TWILIO_PHONE_NUMBER (or any platform/master row) into those inputs as defaults.
3) GET Twilio for Quick Setup: if this company has no TwilioSettings row of its own, return empty sid/token/phone. Filter by the logged-in user’s StaffProfile company_id only. Never first() across the table. Never match by created_by email of a different company.
4) If a stored account_sid does not start with "AC", treat it as junk for this form — show blank, do not paint it into the inputs.
5) Leave the “Not connected” rule as-is: connected only when THIS company’s row has a real AC… SID AND a phone.
